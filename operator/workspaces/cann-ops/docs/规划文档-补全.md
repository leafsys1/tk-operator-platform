## 一、需求背景

目标：在 910B1（`dav-2201`）上交付逐元素减法算子 `elementwise_sub`：`y = a - b`，`alpha` 非 1 时按
torch 语义 `y = a - alpha*b`；对外可被 Python 直接调用（ctypes + host C ABI），并纳入四动作门禁
（build / smoke / test / benchmark）。

起点：`ops/elementwise_add` 已跑通「Ascend C 直调 + 参数化 CLI + 拒绝码 + 精确用例」的框架；
本任务在此框架上验证**带参数（alpha）与带输出复用（out=）**的算子如何分层实现而不破坏门禁协议。

规格来源：`tasks/elementwise_sub/spec/spec.json`（**v2**，spec_version_id 3）。v2 相对 v1 的实质变更：
真机编译证实 DaVinci vector 核不支持 double，device 侧无法复刻 oracle 的「双精度求值 + 单次舍入」，
故明确 alpha≠1 的求值口径为 fp32「先舍入 `alpha*b` 再相减」，并限定 `|alpha*b| ≤ FLT_MAX`；
alpha 为 2 的幂时该式与 oracle 逐位等价。

用例来源：按规格自动生成，2026-10-23 在对话中整组确认后落盘（当前 `cases@8df658c27183dac8`，
by=chat:job#21，07:23:58）。v2 下对用例的两处调整：`sub_alpha_004` 的 b 改走 normal 分布以落入
`|alpha*b| ≤ FLT_MAX` 前提；`sub_rej_006/007` 增加 `argv` 字段（drop `--in-b` / append `--foo 1`），
使参数级拒绝用例可被共享 runner 表达。

## 二、需求分析

- 数学语义：逐元素、无跨元素依赖；IEEE 754 减法结果唯一，NaN/±Inf/±0 需按位正确。
- 输入输出：`a`、`b` float32 连续、同 shape（不广播），`N ∈ [1, 1048576]`；`y` float32 同 shape 连续。
- 参数接口：对齐 `torch.sub(input, other, alpha=1, out=None)`；alpha 任意值；`out=` 可复用（含原地）。
- 拒绝行为（7 类）：N=0、N=1048577、形状不一致、dtype float16、dtype int32、参数缺失、未知参数；
  拒绝码类别与 torch CPU 一致（文本不逐字比对）。
- 参考实现：CPU fp64 计算后一次舍入到 fp32；**禁止**用 NPU 实现作参考。
- 判据：规格文本要求按位精确；门禁口径为 `criteria/ops-precision-standard@1`。
- 性能：仅设备侧 Task Duration，同卡同规模与 `torch.sub` 对比，主用例 N=1048576，alpha=1。

## 三、需求详细设计

1. **调用面分离**：可执行文件 CLI 保持 `run_cases.py` 的固定协议（alpha=1，因为「未知参数必须拒绝」
   使得协议本身是接口）；alpha / out 走 Python 接口 `sub(a, b, alpha=1, out=None)`。
2. **Host**：先做全部参数校验（拒绝码机判），再建 ACL 上下文；按运行时向量核数分核，tile 在
   ≤64K 时取 512、否则 4096；尾块用 `DataCopyPad`。
3. **Kernel**：`CopyIn → Sub → CopyOut` 三段 + double buffer；每块推进 GM 偏移；单入口
   `elementwise_sub_kernel`，可执行文件与共享库共用同一份 kernel 源码。
4. **alpha 实现**：接口层先用缩放 kernel（`Muls(m, b, alpha)`）算 `m = b*alpha`，再 `y = a - m`。
   两次都在候选 kernel 上计算，包装层不代算；不用 `b - b*(1-alpha)` 恒等式（二次舍入，与 torch 不一致）。
   缩放 kernel 与主 kernel 同文件、同 tiling 分块，只换计算原语。
5. **Python 接口**：ctypes 加载 `libelementwise_sub_host.so`，导出
   `elementwise_sub_run(a, b, out, n, dtype_code, device_id)` 与
   `elementwise_sub_scale_run(x, out, n, alpha, device_id)`，返回码与 CLI 一致；Python 层做参数校验并用
   异常类型/消息表达拒绝码。

## 四、特性交叉分析

| 维度 | 设计结论 |
|---|---|
| dtype | 仅 float32；fp16/bf16/int 走拒绝分支 |
| 动态 shape | N 运行时确定，tiling 自适应，N=1 与 N=1M 同一 kernel |
| 原地 / out 复用 | 支持 `out=a`；按块读全部在写之前完成，块间地址不重叠 |
| 多流 / 并发 | 每次调用独立 stream，kernel 后同步一次，返回即数据就绪；ACL 上下文生命周期交给调用方 |
| 图模式 / 混合精度 / 量化 | 不适用（直调二进制、fp32 only） |
| 风险 | 判据档是混合容差而非按位；本算子以 fp64 golden 一次舍入应做到逐位一致，pytest 额外报告按位不一致数 |
| 风险 | 设备侧 Sub 对次正规数是否 FTZ：`UNKNOWN`，由数值边界用例在真机确认 |

## 五、可维可测分析

- **正确性用例**（29 条）：常规 9 条（N 扫描 6 + alpha 3）、数值边界 11 条、边界 1 条（原地 out=a）、
  异常 7 条；回归组初始为空，发现缺陷后补最小复现用例并重新确认用例组。
- **性能用例**（7 点）：N ∈ {1, 1024, 4093, 65536, 262144, 524288, 1048576}，主用例 1M。
- **独立参考**：`ops/elementwise_sub/scripts/golden.py`（CPU fp64，不依赖任何 NPU/torch 计算）。
- **门禁**：`scripts/nm.sh --op elementwise_sub --action build|smoke|test|benchmark`；smoke 必须在 build 之后、
  正式 test 之前通过。
- **可维护性**：新增目录 `ops/elementwise_sub/`、`cases/elementwise_sub/`、`docs/elementwise_sub/`、
  `tests/test_elementwise_sub.py`、`tools/torch_sub_baseline.py`（新增）。另对共享 runner 做了两处
  向后兼容修复：`tools/gen_inputs.py`（`gen_a/gen_b` 为 `null` 的拒绝用例不再抛 `AttributeError`）、
  `tools/run_cases.py`（支持用例用 `argv` 字段表达参数级拒绝）。
- **可测性**：所有用例固定种子、输入裸二进制落临时目录；失败用例保留 a.bin/b.bin/out.bin 作为可复现证据。
