# 算子开发智能体操作手册

> 适用版本：2026-10-28 当前版本
>
> 适用对象：算子需求人员、算子开发人员、测试/性能人员、项目管理员
> 部署形态：本机单用户 Web 控制台 + 远端昇腾 NPU 执行服务器

## 1. 手册目的

本系统用于管理一条完整的昇腾算子研发链路：

```text
需求输入
  → 对话澄清与规格定版
  → 精度/性能用例确认
  → 智能体开发
  → 编译
  → 最小用例冒烟
  → 完整正确性测试
  → 性能基准与性能采集
  → 自动优化和同条件 A/B
  → 版本确认
  → 交付包生成
```

系统的判断依据是规格、代码快照、用例集、真实执行记录和机读报告，不以对话中的“已经完成”作为验收结论。

## 2. 使用角色

| 角色 | 主要操作 |
|---|---|
| 需求人员 | 创建任务、描述算子、上传设计文档、确认规格和用例 |
| 开发人员 | 在任务对话中开发、查看代码和 diff、处理构建或测试问题 |
| 测试/性能人员 | 执行 smoke/test/benchmark/profile，检查报告与门禁 |
| 项目负责人 | 创建优化轮次、采纳/否决优化、管理版本、生成交付包 |
| 管理员 | 配置模型 API、远端服务器、SSH 私钥、开发镜像和价格 |

当前系统按“本机、单用户”设计，不提供登录、租户或多人权限隔离。

## 3. 启动系统

### 3.1 一键启动

在项目根目录执行：

```bash
scripts/dev.sh
```

脚本会启动：

- FastAPI 后端：`127.0.0.1:8077`
- Vite 开发服务：`127.0.0.1:5173`

浏览器打开：

```text
http://127.0.0.1:8077/
```

按 `Ctrl-C` 可以一起停止前后端。

### 3.2 启动前检查

首次使用前至少确认：

1. “API 管理”存在可用的当前模型端点；
2. “服务器与镜像”存在远端执行服务器；
3. SSH 探针通过；
4. 远端存在可用的算子开发镜像；
5. 镜像已标记为算子开发镜像；
6. 服务器上有空闲 NPU 时才能执行真机动作。

## 4. 首次配置

建议按“API → 服务器 → 镜像”的顺序配置。

### 4.1 配置模型 API

进入左侧导航“API 管理”。

填写：

- 端点名称；
- Base URL；
- 模型名称；
- API Key；
- 输入、输出、缓存读、缓存写单价；
- 密钥环境变量名（可选回退方式）。

操作步骤：

1. 新增端点；
2. 点击“探针”；
3. 探针成功后点击“设为当前”；
4. 检查页面显示的当前端点和模型。

注意：

- API Key 不存入 SQLite；
- macOS 优先保存到 Keychain；
- Linux 优先保存到 Secret Service；
- 无系统密钥库时回退到权限为 `0600` 的本机文件；
- 页面和接口不会回显完整 Key；
- 单价单位为“人民币元/百万 token”。

### 4.2 配置远端服务器

进入“服务器与镜像”，点击新增服务器。

填写：

- 显示名称；
- SSH 目标，例如 SSH config 中的 alias 或 `user@host`；
- SSH 私钥；
- 备注。

私钥可以通过文件选择器上传。系统会把私钥复制到本机受控目录并设置 `0600` 权限。

保存后：

1. 点击“设为测试服务器”；
2. 点击“探针”；
3. 检查 SSH、NPU、Docker、镜像清单等结果；
4. 探针失败时查看页面上的 `probe_error`，不要继续执行算子任务。

### 4.3 配置算子开发镜像

在服务器的镜像列表中选择目标镜像，填写或确认：

- 镜像 digest；
- CANN 版本；
- Python 版本；
- PyTorch/torch_npu 版本；
- 环境启动配方；
- 环境预检命令；
- “测试镜像”标记；
- “算子开发镜像”标记。

镜像能启动不等于能开发算子。test、benchmark、profile 需要镜像具备相应运行时、torch/torch_npu 和 NPU 设备访问能力。

| 页面 | 用途 |

| 任务 | 新建任务、查看草稿和正式任务、进入任务作业台 |
| 阶段看板 | 按真实门禁证据查看任务所在阶段 |
| 测试管理 | 查看精度/性能用例、逐例结果、当前有效与历史失败记录 |

| 消耗情况 | 查看智能体调用量、token 和费用 |

## 6. 新建算子任务

### 6.1 进入任务开始页

在“任务”页面点击“新建任务”。

第一次输入或保存时，系统会先创建草稿任务。草稿可以反复修改，不会立即进入正式开发阶段。

### 6.2 输入需求

支持以下输入形式：

- 自然语言；
- 数学公式；
- 参考代码；
- 输入输出示例；
- `.docx` 或 `.md` 算子设计文档。

建议一次至少说明：

1. 算子做什么；
2. 输入输出 shape、dtype、format；
3. 是否支持广播、动态 shape 或非连续内存；
4. 目标硬件；
5. 参考实现；
6. 期望精度；
7. 需要重点优化的 shape。

### 6.3 上传设计文档

“设计文档”区域支持：

- 下载 `.docx` 模板；
- 下载 `.md` 模板；
- 上传、替换或删除设计文档；
- 单文件最大 20 MB。

系统会保存原文并生成解析稿。原始文档会进入最终交付包。

设计文档不是必需项；没有文档时可以完全通过对话完成需求澄清。

### 6.4 完成需求澄清

左侧对话用于澄清需求，右侧实时显示规格草稿。

重点检查：

- 算子名称是否正确；
- 数学语义是否完整；
- 输入输出是否明确；
- dtype、shape、format 是否明确；
- 支持范围和拒绝范围是否明确；
- 精度判据是否明确；
- 目标芯片和调用方式是否明确；
- 待确认项是否已经清零。

### 6.5 定版

规格状态显示“可定版”后，点击：

```text
确认并定版（生成上下文空间）
```

定版会：

1. 生成 `spec v1`；
2. 生成任务上下文空间；
3. 把草稿转为正式任务；
4. 跳转任务详情页。

定版后算子名被冻结。如果语义、接口或支持范围发生实质变化，应通过任务对话创建新规格版本，而不是直接修改旧规格。

## 7. 确认精度和性能用例

进入正式任务后，第一件事是确认用例组。

在任务“对话”分区中要求智能体生成并展示：

### 7.1 精度用例

至少考虑：

- 常规 shape；
- 边界 shape；
- 非对齐 shape；
- 数值边界；
- 异常和拒绝输入；
- 回归用例；
- 固定随机种子；
- 期望行为和误差标准。

### 7.2 性能用例

至少考虑：

- 主用例；
- 小 shape；
- 大 shape；
- 不同 dtype；
- 语义匹配基线；
- 预热次数和重复次数；
- 聚合方式；
- 是否为 required 用例。

用户在对话中确认整组用例后，智能体写入：

```text
cases/<op>/cases.json
cases/<op>/benchmark.json
```

并调用用例确认接口留下哈希和阶段记录。

未确认用例时，系统会禁止 build、smoke、test、benchmark 和 profile 的真机执行。

如果后续修改用例，旧测试和性能证据会失效，需要重新确认并重跑。

## 8. 任务作业台

任务详情包含八个分区。

### 8.1 概览

用于查看：

- 当前任务版本；
- 当前阶段；
- 用例是否已确认；
- build/smoke/test/benchmark/profile 门禁；
- 真机执行入口；
- 交付门禁。

### 8.2 对话

用于：

- 继续澄清需求；
- 确认用例；
- 开发或修复代码；
- AI 审查某次 Run；
- 发起自动优化；
- 上传附件；
- 回退某轮消息引起的代码修改。

对话可以全屏放大，按 `Esc` 返回原布局。切换分区不会中断正在流式输出的会话。

### 8.3 需求与规格

用于查看：

- 当前规格；
- 规格版本历史；
- 原始设计文档；
- 上下文空间；
- 任务使用的服务器、镜像、设备和超时配置。

规格修改必须通过对话完成。实质变更会形成新大版本，并使旧证据失效。

### 8.4 实现与调用

用于：

- 浏览任务工作区文件；
- 预览源码；
- 查看工作区 diff；
- 查看实现和 Python 调用接口；
- 查看构建相关记录。

### 8.5 测试与结果

用于查看：

- 精度和性能用例；
- 逐例正确性结果；
- 候选与基线耗时；
- 加速比、带宽和 Roofline；
- Profiling 四类指标；
- 报告 JSON 导出。

### 8.6 性能与优化

用于：

- 搜索优化点；
- 管理优化思路池；
- 新建优化轮次；
- 运行基线和候选验证；
- 查看同条件 A/B；
- 采纳或否决；
- 导出优化报告。

### 8.7 版本

用于管理：

- 任务大版本/小版本；
- 版本来源；
- 是否已交付；
- 源码 savepoint；
- 与当前工作区 diff；
- 下载、恢复和删除存档。

### 8.8 记录与交付

用于查看：

- 智能体作业；
- 真机 Run；
- ActionJob；
- 优化轮次关联；
- 当前有效证据；
- 历史失败；
- 交付门禁和交付历史。

## 9. 开发操作

### 9.1 发起开发

在“概览”点击开发入口，系统会跳转到任务对话并预填开发提示。

智能体应生成五类交付物：

1. `ops/<op>/`：算子代码；
2. `ops/<op>/python/<op>.py`：Python 调用接口；
3. `tests/test_<op>.py`：pytest 测试脚本；
4. 算子说明文档；
5. 规划/设计补全文档。

开发完成的口径不是“文件已生成”，而是 build 和 smoke 都通过。

### 9.2 开发中检查

建议随时在“实现与调用”查看：

- 智能体修改了哪些文件；
- 是否写到允许的算子目录；
- 是否存在非预期共享文件修改；
- Python 接口和 C ABI 是否齐备；
- 测试和文档是否齐备。

## 10. 执行真机动作

权威顺序为：

```text
开发 → build → smoke → test → benchmark → profile（可选）→ delivery
```

### 10.1 通用操作方式

在“概览”选择动作：

1. 点击“算计划”；
2. 查看 `ready` 状态和缺项；
3. `ready=true` 后点击“真执行”；
4. 观察实时日志；
5. 等待 Run 和门禁结果；
6. 必要时点击“AI 审查”。

如果没有空闲设备，系统会拒绝执行，不会强占他人使用的卡。

### 10.2 build：编译

检查内容：

- 代码能否编译；
- 可执行文件是否生成；
- Python Host 共享库是否生成；
- 必需符号是否存在；
- 日志和版本信息是否齐备。

### 10.3 smoke：最小用例冒烟

smoke 会自动选择一条最小 required 正常用例，验证：

- 构建产物能够加载；
- Kernel 可以在 NPU 上启动；
- 最小输入可以正确执行；
- 输出能够通过基本判据。

smoke 不代替完整 test。smoke 未通过时不应继续 test 或 benchmark。

### 10.4 test：完整正确性测试

test 会执行已确认的完整精度用例，并与参考实现比较：

- 输出 shape；
- dtype；
- 数值误差；
- 拒绝类输入；
- 逐例 PASS/FAIL/xfail/unsupported。

门禁要求存在可读的 `correctness.json`，且报告版本与当前任务一致。

### 10.5 benchmark：性能基准

benchmark 会在同设备、同环境下比较候选和基线。

重点查看：

- 设备侧中位数耗时；
- 重复次数；
- 候选与基线语义是否一致；
- 主用例和非主用例；
- 小 shape 是否回退；
- 结果是否落在测量不确定性内。

不要使用 Host 墙钟直接宣称算子加速，系统以设备侧执行时间为主要口径。

### 10.6 profile：性能采集

profile 为可选动作，使用 `msopprof` 采集：

- 执行耗时；
- 数据搬运；
- 存储使用；
- 计算单元负载。

不适用于当前算子的指标应显示 `unsupported`，不能伪造为已采集。

### 10.7 取消执行

执行期间可以点击取消。系统会：

- 终止本地进程组；
- 尝试终止远端容器；
- 记录取消状态和清理结果。

取消后仍应到服务器页面或远端检查是否残留容器。

## 11. 查看门禁和历史记录

### 11.1 当前有效证据

一条证据只有同时匹配以下内容才对当前版本有效：

```text
当前规格版本
+ 当前算子代码快照
+ 当前用例集哈希
+ 当前动作门禁 PASS
```

### 11.2 历史失败

历史失败不会被删除。页面将其与“当前有效”记录分开显示。

看到失败记录时先确认：

- 是否属于旧代码快照；
- 是否属于旧用例集；
- 是否是环境或设备占用问题；
- 是否已被后续同版本 PASS 证据替代。

不能因为历史中存在失败就直接判断当前版本失败，也不能因为历史中存在一次 PASS 就判断当前代码仍然有效。

## 12. 结果解读

### 12.1 正确性结果

主要看：

- 总用例数和通过数；
- 最大绝对/相对误差；
- 失败集中在哪类 shape；
- 异常输入是否按预期拒绝；
- 是否存在 unsupported，而不是被记成 PASS。

### 12.2 性能结果

主要看：

- 主用例候选耗时；
- 基线耗时；
- 加速比；
- 置信区间或不确定性；
- 其它 shape 是否退化；
- 设备、镜像和代码快照是否一致。

### 12.3 Roofline 和带宽

对于有可靠算术强度画像的算子，页面会给出带宽受限或计算受限判断。

矩阵、Attention 等算术强度随 shape 变化的算子，如果报告没有可靠画像，系统不会强行下 Roofline 结论。

## 13. 自动优化

### 13.1 搜索优化点

在“性能与优化”点击优化点搜索。

诊断智能体只读现有代码、报告和历史结论，最多返回有限数量的高价值新思路。诊断任务不允许修改代码，也不允许发起真机动作。

每条优化思路应包含：

- 优化点标题；
- 瓶颈假设；
- 修改范围；
- 预期收益；
- 风险；
- 验证方法。

### 13.2 新建优化轮次

可选择：

- 目标类型：性能、精度、硬件适配；
- 目标维度：指定用例、全部用例、文字优化点；
- 目标用例；
- 不允许退化的约束；
- 每动作执行预算；
- 用户补充思路；
- 是否复用已有基线证据。

一条思路只能同时对应一个未关闭的优化轮次。

### 13.3 跑基线

基线至少包含：

- test；
- benchmark；
- 基线代码 savepoint。

基线证据未齐时不能启动受控自动优化。

### 13.4 启动自动优化

点击“自动优化”后会跳转任务对话。

在对话中发送参考指令，智能体会收到本轮目标、允许路径、预算、基线和现有报告，只能修改本轮允许的算子目录。

完成后检查：

- 修改文件；
- unified diff；
- 修改后快照；
- verifier 结果；
- 是否发生自动回退；
- 是否仍有未提交或越界修改。

### 13.5 跑候选验证

点击“跑候选验证”，系统按顺序执行：

```text
test → benchmark
```

如果智能体在候选验证后又修改代码，旧候选证据会失效，需要重新验证。

### 13.6 查看 A/B

对比页面展示：

- 优化前/后代码快照；
- 两侧 test 和 benchmark Run；
- 精度是否退化；
- 各用例耗时和变化百分比；
- improved、regressed 或 no_significant_change；
- 结构化建议和验证方法。

### 13.7 采纳或否决

采纳：

- 候选成为新的任务小版本；
- 绑定候选代码快照和验证证据；
- 建立采纳存档；
- 可以继续进入交付。

否决：

- 关闭轮次；
- 标记本思路无效；
- 可以选择把工作区回退到优化前状态；
- 失败结论作为以后搜索优化点的负样本保留。

自动优化永不自动采纳，最终决定由用户完成。

## 14. 版本、存档和回滚

### 14.1 任务版本

任务版本显示为：

```text
v大版本.小版本
```

- 大版本：需求或规格发生实质变化；
- 小版本：采纳优化或交付前人工代码变更。

### 14.2 源码 savepoint

可以手动建立源码存档，也会在关键操作前自动建立存档。

支持：

- 查看存档详情；
- 与当前工作区比较；
- 下载归档；
- 恢复任务目录；
- 恢复完整工作区；
- 删除存档。

恢复前系统会建立急救存档。存在运行中作业时禁止恢复，避免破坏执行中的快照。

## 15. 生成交付包

进入“记录与交付”或概览中的交付入口。

### 15.1 交付前检查

系统会检查：

- 用例已确认且未变；
- 当前规格有效；
- 当前代码快照有效；
- build PASS；
- smoke PASS；
- test PASS；
- benchmark PASS；
- 五件交付物齐备。

profile 是可选项，不影响基本交付门禁。

### 15.2 生成交付包

门禁齐备后点击“生成交付包”。

交付 ZIP 包含：

- 算子代码；
- Python 调用接口；
- pytest 测试脚本；
- 精度和性能用例；
- Golden 参考实现；
- 算子说明文档；
- 原始和补全规划文档；
- correctness/performance 证据；
- `manifest.json`。

### 15.3 交付失败

生成失败时根据缺项操作：

| 缺项 | 处理方式 |
|---|---|
| 用例未确认 | 回到对话确认精度/性能用例 |
| 代码快照不一致 | 对当前代码重新执行 build/smoke/test/benchmark |
| 用例集已变化 | 重新确认并重跑 test/benchmark |
| 缺 Python 接口 | 让智能体补 `ops/<op>/python/` 和 Host C ABI |
| 缺测试脚本 | 补 `tests/test_<op>.py` |
| 缺文档 | 补算子说明和规划文档 |
| test/benchmark 失败 | 修复后按当前版本重跑 |

交付后再修改代码，需要形成新版本并重新验证、重新交付。

## 16. 阶段看板

阶段看板不是手工状态表，而是根据真实证据推导：

| 阶段 | 主要条件 |
|---|---|
| 需求与设计 | 规格和用例组尚未完整确认 |
| 开发 | 用例已确认，正在实现或 build/smoke 尚未齐备 |
| 验证与优化 | build/smoke 已过，test/benchmark 或优化仍在进行 |
| 交付 | 当前版本 delivery 门禁通过 |

页面提供“按证据同步”，用于把推导阶段写回任务并留下阶段事件。

## 17. 测试管理

测试管理页面可以按任务查看：

- 精度用例矩阵；
- 性能用例矩阵；
- 每条用例的执行历史；
- 最近通过结果；
- 失败点；
- 当前有效证据；
- 历史失败；

测试管理主要用于跨任务查看，不替代任务详情中的结果页。

## 18. 案例库

案例库支持：

- 从独立 ZIP bundle 导入案例；
- 查看案例名称、场景和目标芯片；
- 一键创建任务。

当前案例库框架已经完成，但“内置不少于 10 个典型算子案例”的正式内容仍在建设中。不要在内部验收中把案例库框架表述为 10 个案例已经完成。

## 19. 消耗情况

“消耗情况”只统计真实智能体调用，示例数据不计入。

可以查看：

- 输入 token；
- 输出 token；
- 缓存读/写 token；
- 调用次数；
- 模型和端点；
- 按 API 单价计算的人民币费用。

早期没有绑定端点的调用可能按当前端点估算，页面会进行标记。

## 20. 常见状态说明

| 状态 | 含义 |
|---|---|
| pending | 已创建，等待执行 |
| running | 正在执行 |
| ok | 进程执行完成且退出码正常，不等于门禁一定通过 |
| failed | 执行失败 |
| interrupted | 被取消或进程中断 |
| env_failed | 环境、设备、镜像或锁问题，通常不属于算子缺陷 |
| gate pass | 当前动作证据满足门禁 |
| gate warn | 可继续，但存在非阻断风险 |
| gate fail | 不能作为当前版本有效证据 |

## 21. 常见问题排查

### 21.1 “没有空闲设备”

原因：共享服务器上的 NPU 正被其他进程占用。

处理：

1. 到“服务器与镜像”重新探针；
2. 等待空闲设备；
3. 不要强行关闭他人的进程或容器；
4. 确认上一次任务没有残留容器。

### 21.2 “用例组未确认”

原因：当前任务还没有完成精度/性能用例整组确认，或用例文件发生变化。

处理：回到任务对话，展示并确认两组用例，重新写入确认哈希。

### 21.3 “代码快照不一致”

原因：执行以后代码又被修改，旧 Run 不再对应当前工作区。

处理：确认修改合理后，从 build 开始重新运行当前版本。

### 21.4 “用例集不一致”

原因：`cases.json` 或 `benchmark.json` 已变化。

处理：重新确认用例组，再运行 test 和 benchmark。

### 21.5 build 成功但 smoke 失败

常见原因：

- Kernel 启动参数错误；
- Host/Tiling 与 Kernel 不一致；
- 设备或 stream 初始化错误；
- 输入输出 buffer 大小错误；
- 最小用例不在真实支持范围。

处理：先修 smoke，不要直接进入完整 test。

### 21.6 test 退出码为 0 但门禁失败

常见原因：

- 缺少 `correctness.json`；
- 报告无法解析；
- 报告中的规格、代码或用例版本不匹配；
- 必需用例没有结果；
- unsupported 被错误标成 PASS。

以门禁失败码为准，不以进程退出码代替验收。

### 21.7 benchmark 看起来有巨大加速

先检查是否比较了：

- 相同语义；
- 相同设备；
- 相同 dtype/shape；
- 设备侧时间；
- 相同预热和重复次数。

如果一侧是 Host 墙钟、一侧是设备侧时间，结果不可用于性能结论。

### 21.8 取消后设备仍被占用

处理：

1. 查看 ActionJob 日志中的远端清理结果；
2. 重新运行服务器探针；
3. 到远端检查任务容器；
4. 只清理本系统明确创建的容器，不处理未知容器。

### 21.9 模型调用 401/403

处理：

1. 检查“API 管理”的当前端点；
2. 重新保存 Key；
3. 运行端点探针；
4. 检查模型名和 Base URL；
5. 必要时重启系统，让运行时路由重新生成。

### 21.10 页面显示历史失败，但任务已经交付

这是正常的审计行为。历史失败会被保留。

判断当前状态时看：

- “当前有效”标记；
- 当前版本证据；
- 交付门禁；
- 最新交付包。

## 22. 日常操作建议

1. 每次开发前先确认规格和用例；
2. 代码写完必须先 build，再 smoke；
3. 性能结论必须来自同设备、同镜像、同用例条件；
4. 修改用例后重新确认，不复用旧结果；
5. 优化一次只验证一个主要假设；
6. 优化不显著或发生回退时如实否决；
7. 交付前检查当前代码是否有未验证修改；
8. 共享机器上不抢卡、不杀未知进程；
9. 不在日志、文档或对话中粘贴完整 API Key；
10. 对外说明时区分“框架已完成”“真机已通过”“已正式交付”三种状态。
