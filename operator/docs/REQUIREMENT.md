## 一、现行需求（2026-10-15，原文照抄）

> 算子开发能力： 支持通过自然语言、数学公式及参考代码自动生成算子实现代码、调用接口和测试脚本，内置不少于10个典型算子开发案例，覆盖矩阵计算、归一化、激活函数、注意力机制等场景。
>
> 算子自动优化能力： 支持算子正确性验证、性能瓶颈分析及自动优化，能够基于目标硬件特性生成优化代码，并完成优化前后的精度与性能对比，形成可复现的测试报告。

### 1.1 与原始需求的差异（逐条）

| # | 差异 | 性质 |

| D1 | 「**辅助**生成算子实现代码、调用接口和测试脚本」→「**自动**生成…」 | 措辞升格；主流程本已自动产出三件产物，人工只在澄清与审批 |
| D2 | 新增「**内置不少于 10 个典型算子开发案例**，覆盖矩阵计算 / 归一化 / 激活函数 / 注意力机制」 | **全新硬指标**（原始需求完全没有） |

### 1.3 已定口径（2026-10-20 定稿）

1. **案例库深度**：10 个案例全部齐备（规格 / 用例 / 参考实现 / 实现代码 / 基线）；**10 个全部完成真机全链路（硬性）**——不设「≥3 个」底线、不留离线降级出口。**交付形态 = 独立 zip bundle + 导入脚本**（仓库不预置案例，2026-10-20 定）；导入后落 `cases/<op>/`。**算子清单不写死**：某个算子开发受阻时可在**同场景内替换**，但必须保持 10 个案例、四场景覆盖与全部真机全链路。M2 仍**最后做**（2026-10-19 定）。
2. **自动优化验收口径**：**完成闭环 + 对比报告** —— 必须真的做优化前后**同条件 A/B** 并出报告；**提升是否显著如实报告，不设加速比硬线**。验收以**至少一份有效报告**为准（不要求每个案例都做优化）。「自动」= agent 执行 + 工具判定；人保留触发、审批（定版/采纳）与回退权。
3. **D8 执行预算**：从「每任务 ≤6 次」改为**按案例 / 按 Loop 计**（每案例 `build`/`test`/`benchmark`/`profile` 各 1–2 次），**受控修复仍 3 轮上限**，环境/契约类失败仍不计入。当前为人工核对口径。
4. **需求文本关系**：**分层**——现行需求置顶，原始文本（附录 A）仅作溯源（2026-10-20 定）。
5. **真机全链路定义**：规格定版 → 实现代码 → `build` → `test`（用例全过）→ `benchmark` → **门禁 pass**，产物/快照/版本可追溯；`profile` 可选。
