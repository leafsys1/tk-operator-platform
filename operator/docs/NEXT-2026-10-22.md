## 2. 三种工作模式

| 模式 | 前提 | 能做什么 |
|---|---|---|
| **模式① 只有代码（推荐先做）** | 无硬件/无 Lead DB | 「优化点搜索 / 测量预算」后端 + 单测、前端 UI（无真实数据时靠 tsc/build 与临时库）、代码审查；不能做真实 A/B |
| **模式② 沿用 Lead 运行数据（“继承实机状态”）** | 同一绝对路径 + 复制 gitignored 状态 + SSH/key | 完整复现 Loop #6 与报告；见 §3 |
| **模式③ 自己的实机** | 自己的 DB + 主机/镜像/key | 从零建任务→基线→优化轮次；不能操作 Lead 的任务 |

### “继承 Lead 实机状态”到底指什么

**Lead = 我当前这台开发机/这个会话**。git 仓库里只有代码、文档和工作区交付件；任务、轮次、run、存档、报告、skills、真实库都在我机器的本地目录里（被 `.gitignore` 排除）。

**“继承” = 把这些不在 git 里的运行数据复制到你的机器上，让你打开页面时看到和我一样的任务 #11 / Loop #6 / baseline 存档 / 历史 run / 报告，接着跑 A/B；它不是 `git checkout`，也不会从仓库自动恢复。** 常见做法：

- 停掉 8077 后复制 `backend/opx.db`
- 复制 `archives/`（源码归档）与 `runs/`、`workspaces/cann-ops/runs/`（run 产物）
- 复制 `workspaces/cann-ops/.dsh/`（skills）或重跑 `scripts/install_skills.sh`
- 提供 `~/.config/op-agent/env` 里的 LLM key（或页面端点 key）
- 保持**同一绝对路径**（DB 里存的是绝对路径）；否则报告/回滚会找不到文件
- 还需要有同样的 tk36/镜像访问权，否则只能看历史，不能继续跑

**不继承也完全能开发**：模式①（只做代码/单测）或模式③（自己的任务从零开始）。只有你需要“接着我的 Loop #6 继续跑 A/B”且能拿到同路径/SSH/key 时，才用模式②。

**模式② 需要复制（都是 gitignored）**：
- `backend/opx.db`（停服务后 `cp`；不要带 `-wal/-shm` 或先 checkpoint）
- `archives/`（savepoint 源码归档）
- `runs/` 和 `workspaces/cann-ops/runs/`（run 产物；两处历史上都可能有）
- `workspaces/cann-ops/.dsh/`（skills；也可用 `install_skills.sh` 重建）
- `~/.config/op-agent/env`（若用环境变量 key）或页面端点 key
- 可选：`.opx-chat/`、`tasks/`

⚠️ **绝对路径**：`projects.workspace_path`、`runs.manifest_path`、`savepoints.archive_path` 存的是绝对路径。若 clone 路径不是 `/Users/lfx/Projects/personal/op-agent`，要么保持同一路径，要么改 DB（project.workspace_path）并设置 `OPX_SAVEPOINT_ROOT` 指向归档根；否则「对比/回滚/报告」会找不到文件。

## 6. 坑（今天踩过的）

1. **快照口径**：`nm_test.sh` 与 `exec_actions.snapshot` / 存档 archiver 的 skip 集必须一致（已补 `.opx-chat` 与 `test_snapshot.py`）。再改任一处 skip/排序先跑该测试。
2. **基线不是“存档 sha”**：历史数据可能 `baseline 存档 sha ≠ run sha`；候选识别/报告已改为优先按「本轮最早 ok run / perf-diff sides」，不要只信存点 sha。
3. **远端输出延迟**：test/benchmark 日志可能长时间静止，看「已运行时长」；超时 1800s。
4. **刷新恢复**：验证中刷新会接管 running job；两个动作之间刷新则卡片显示缺哪个动作。
5. **不自动采纳**：需求要求人保留审批/回退权；自动采纳会重演「agent 说没改、实际留空白」的坑。
6. **真实库测试**：Loop 无删除接口；别在真实任务反复建测试轮次，优先临时库/DB 副本。
7. **gitignore**：DB/runs/archives/skills/venv/node_modules/dist/nm.conf 都不入库；`web/.npm-cache/` 已忽略。
